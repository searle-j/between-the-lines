## 세 줄 요약

- 하네스 최적화는 보통 수정된 하네스를 바로 채택하지 않고 한 번 일부 과제에 테스트한 다음에 채택한다.
- 그런데 이번의 수정 목적과 무관한 과제들에 테스트할 필요가 있을까? 그러면 비용도 많이 들고 테스트 결과에 노이즈도 생겨버린다.
- 그러니까 매번 수정 목적에 부합하는 과제들만 골라서 테스트해야 하는데, 이걸 에이전트가 잘 골라줄 수 있다는 얘기.

---

## 요약

### 문제 의식

- 하네스 최적화는 '수정안 제안 -> 검증'을 반복한다. 검증은 이번에 수정된 하네스로 일부 과제를 다시 풀어서 진짜 점수가 오르는지 확인하는 단계인데, 이 단계에서 탈락하면 당연히 그 하네스는 버려진다.
- 그런데 수정안마다 고치려는 목표 지점이 다 다를 것이다. 그러므로 이번의 수정 목표와 무관한 과제들을 풀어서 검증하는 것은 비용이 늘어날 뿐만 아니라 제대로 된 검증도 아니다.
- HarnessLens는 수정안마다 관련 있는 과제를 골라서 검증하는 식으로 비용은 줄이고 평가 정확도는 올리는 기법이다.

### 제안하는 기법

- HarnessLens의 알고리즘은 아래와 같은 루프이다. 루프 안에는 역할이 다른 에이전트 네 종류 존재.
- 먼저 초기 하네스로 과제를 전부 풀어서 실행 로그를 모아 둔다. 이때 과제들을 목적이 비슷한 것끼리 묶어 두고, 하네스에서 고칠 수 있는 부분이 (e.g., 지침, 스킬, 도구 설명) 무엇인지도 파악해 둔다.
- 이제 준비가 되었으면 아래 루프를 돌린다.
	1. 수정안 만들기
		- 진단 에이전트가 실행 로그 전체를 확인하여 반복되는 결함을 찾고, 이를 해결할 수정 제안서를 쓴다.
		- 개선 에이전트가 제안서 중 제일 괜찮은 거 하나를 고른다.
		- 편집 에이전트가 선택된 제안서대로 현재 하네스에 패치를 날린다.
	2. 검증할 과제 고르기: 개선 에이전트가 그 수정과 관련 있는 과제를 5개 이상 고르는데, 이때 이 패치 덕분에 개선될 것 같은 과제와 이 패치 때문에 망가질 것 같은 과제, 이 두 가지를 적절히 섞어서 고름.
	3. 검증 보고서 작성: 고른 과제들을 기존 하네스와 패치된 버전으로 푼다. 그 다음에 비교 에이전트가 두 하네스의 로그를 비교하여 보고서를 작성한다. 보고서에서는 점수 향상이 정말 패치의 의도대로 일어난 것인지 분석한다.
	4. 검증 판단: 이제 진단 에이전트가 지금까지 만든 모든 검증 기록을 가지고 판단을 내린다. 패치 덕분에 나아진 과제가 있고 수정 때문에 망가진 과제는 없어야 통과.
	5. 최종 채택: 통과한 하네스는 새로운 과제들에 대해 검증을 한 번 더 거친다. 여기서도 한 번 더 통과해야 최종적으로 채택.
	6. 다시 1번으로 돌아가 반복. 단, 검증 과정에서 발생한 에이전트 로그들은 다음 턴에 에이전트가 열람할 수 있도록 기록된다.

### 실험 조건

- 모델: deepseek-v4-flash-preview (모든 에이전트에 사용)
- 하네스: OpenCode, Codex CLI, Pi Coding Agent
- 벤치마크: tau2-bench Retail (쇼핑몰 고객 상담), tau3-bench Banking Knowledge (은행 고객 상담), Terminal-Bench 2.0 (터미널 작업), BIRD Mini-Dev (SQL 작성). 훈련 과제는 각 30개.
- 비교 대상: 기존의 하네스 최적화 기법들...
- 주요하게 볼 것은 HarnessLens가 예산을 훨씬 덜 쓰고도 더 좋은 하네스를 만드는지.

### 실험 결과

- HarnessLens가 경쟁 기법들 대비 가장 적은 예산으로 가장 좋은 성적을 냈다. 12개 조합 (하네스 3개 x 벤치마크 4개) 중 8개에서 1등 혹은 공동 1등.
	- 주목할 만한 지점: 초기 하네스보다 나빠진 경우가 한 번도 없었다. 반면에 Self-Harness와 Meta-Harness는 절반의 경우에서 초기 하네스보다 나빠졌다.
- 점수만 봤다면 통과했을 수정안도 걸러냈다. 예컨대, 검증 점수가 50%p나 올랐는데도 노리던 행동 변화가 확인되지 않아서 탈락한 수정안이 있었다.
- 한편, 범용적으로 통하는 하네스를 만들기는 어려웠다. BIRD처럼 여러 과제가 비슷한 결이면 잘 통했지만, Terminal-Bench처럼 과제마다 목표가 제각각이면 두루 통하는 하네스를 찾지는 못함.
