## 세 줄 요약

- 하네스를 자동으로 개선하는 기법들은 보통 수정안이 나올 때마다 미리 정해 둔 과제 묶음을 다시 풀어서 검증한다.
- 그런데 수정안마다 고치려는 행동이 다른데도 전부 같은 과제로 검증하다 보니, 예산은 낭비되고 정작 그 행동이 바뀌었는지는 합산 점수에 묻혀 버린다.
- HarnessLens는 수정안마다 관련 있는 과제를 골라서 검증하고, 점수가 올랐더라도 노리던 행동이 실제로 바뀐 경우에만 채택한다.

## 요약

### 문제 의식

- 하네스 개선 기법들은 '수정안 제안 -> 검증'을 반복한다. 검증은 과제를 다시 풀어서 점수가 올랐는지 보는 단계인데, 보통 모든 수정안을 같은 과제 묶음으로 검증한다.
- 그런데 수정안마다 고치려는 행동이 다르다. 그러다 보니 그 수정과 상관없는 과제까지 푸느라 예산이 낭비되고, 여러 과제의 점수를 합산해서 보니 노리던 행동이 정말 바뀌었는지도 다른 데가 망가졌는지도 잘 안 보인다.
- 그렇다면 수정안마다 관련 있는 과제를 골라서 검증하면 되지 않을까? 이것이 HarnessLens의 출발점.

### 제안하는 기법

- 여기서 '행동'은 실행 로그에서 반복해서 보이는 패턴을 말한다. 즉, 에이전트가 어떤 조건에서 무엇을 어떤 순서로 하는지. 점수가 같아도 행동은 다를 수 있다.
- HarnessLens는 이런 루프를 돈다. 먼저 초기 하네스로 훈련 과제를 전부 풀어서 실행 로그를 모아 둔다.
	1. 수정안 만들기: 실행 로그에서 반복되는 결함을 찾아 수정안을 만든다. 수정안마다 고치려는 행동과 근거가 된 로그가 붙는다.
	2. 검증할 과제 고르기: 그 수정으로 고쳐져야 할 실패 과제와 망가지면 안 되는 성공 과제를 섞어서 5개 이상 고른다.
	3. 검증: 고른 과제를 현재 하네스와 수정안으로 각각 풀고 두 로그를 비교한다. 수정 덕분에 나아진 과제가 있고 수정 때문에 망가진 과제는 없어야 통과.
	4. 채택: 통과한 수정안은 다른 과제 묶음으로 한 번 더 확인한 뒤 채택한다. 즉, 점수만 올라서는 채택되지 않는다.
	5. 다시 1번으로 돌아가 반복. 검증하면서 나온 로그는 다음 수정안의 재료가 된다.

### 실험 조건

- 모델: deepseek-v4-flash-preview (과제 풀이와 하네스 개선 모두 이것만 사용)
- 하네스: OpenCode, Codex CLI, Pi Coding Agent
- 벤치마크: tau2-bench Retail (쇼핑몰 고객 상담), tau3-bench Banking Knowledge (은행 고객 상담), Terminal-Bench 2.0 (터미널 작업), BIRD Mini-Dev (SQL 작성). 훈련 과제는 각 30개.
- 비교 대상: 초기 하네스, Self-Harness, [Meta-Harness](meta-harness.ko.md), HarnessFix
- 예산: HarnessLens는 과제 실행과 LLM 호출을 합쳐서 200회. 비교 기법들은 각자의 원래 설정대로 과제 실행만 최대 4,800회 (Self-Harness), 660회 (Meta-Harness), 300회 (HarnessFix).
- 주요하게 볼 것은 HarnessLens가 예산을 훨씬 덜 쓰고도 더 좋은 하네스를 만드는지.

### 실험 결과

- 가장 적은 예산으로 가장 좋은 성적을 냈다. 12개 조합 (하네스 3개 x 벤치마크 4개) 중 8개에서 1등 혹은 공동 1등.
- 초기 하네스보다 나빠진 경우가 한 번도 없었다. 반면에 Self-Harness와 Meta-Harness는 절반의 경우에서 초기 하네스보다 나빠졌다. 즉, 검증에 예산을 많이 쓴다고 더 좋은 하네스가 나오는 게 아니다.
- Ablation: 과제를 골라서 검증하는 것과 행동 변화를 확인하고 채택하는 것, 둘 다 필요했다. 하나라도 빼면 초기 하네스에서 거의 나아지지 않았다.
- 점수만 봤다면 통과했을 수정안도 걸러냈다. 예컨대, 검증 점수가 50%p나 올랐는데도 노리던 행동 변화가 확인되지 않아서 탈락한 수정안이 있었다.
- 단, 과제 구성을 탄다. BIRD처럼 여러 과제가 같은 판단을 공유하면 잘 통했지만, Terminal-Bench처럼 과제마다 목표가 제각각이면 두루 통하는 수정안을 찾기 어려웠다.
