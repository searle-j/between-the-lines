## 세 줄 요약

- ActiveSaddler는 하네스 최적화를 커리큘럼 학습으로 정식화한다. *(작성자 주. 커리큘럼 학습은 학습에 쓰는 과제의 순서를 조절하는 기법이다. 쉬운 과제에서 어려운 과제로 넘어가는 게 대표적. 예컨대 로봇 팔에게 점점 더 복잡한 형체의 물체를 옮기게 한다든지.)*
- 매 라운드 에이전트는 과거의 실패를 고칠지 혹은 새로운 문제에 도전하여 실패를 발굴할지 정하여 작업한다.
- 무작위로 정한 고정 순서보다 더 적은 실행으로 더 높은 검증 점수에 도달했다.

## 요약

### 문제 의식

- 여러 과제에 범용적으로 먹히는 하네스를 만들고 싶을 때 흔히 과제를 배치로 쪼개어 에이전트에게 하나씩 주면서 개선을 요구하곤 한다.
- 그런데 에이전트에게 과제 순서를 무작위로 제공하는 것이 최선일까? 커리큘럼 학습처럼 더 효과적인 순서를 찾아볼 수는 없을까?

### 제안하는 기법

- 아래 순서로 반복한다. 먼저 과거의 실패들이 유형화되어 있는 실패 패턴 리스트가 있다. 각 실패 패턴에는 과제들이 대응되어 있다. e.g., `"날짜 오류": ["과제 5", "과제 13"]`
	1. 새 과제와 기존 실패 중 고르기: 에이전트가 지금까지의 실험 이력 전체를 보고 둘 중에 하나를 고른다.
		- 새로운 과제를 풀어서 실패 패턴을 발굴할 것인가
		- 혹은 실패 패턴 중 하나를 골라 고칠 것인가
	2. 만약 새로운 문제를 선택했다면
		- 아직 안 푼 문제를 최대 세 개 뽑는다.
	3. 만약 실패 패턴을 고치고자 한다면
		- LLM이 최근 실행과 패치 이력을 읽고 실패 패턴마다 0-1점으로 우선순위를 매긴다. 지금도 문제인지, 하네스를 고쳐 해결할 수 있는지, 다른 과제에도 도움이 될지, 이걸 고쳐서 얻을 수 있는 이득이 위험 대비 큰지. (점수는 매번 새로 매김... 그 사이에 해결되었을 수도 있으니...)
		- 점수가 높은 패턴일수록 뽑힐 확률이 높다. 이렇게 현재 하네스의 약점 하나를 고른다.
		- 이 실패 패턴에 연결된 문제를 최대 세 개 뽑는다.
	4. 둘 중에 무엇을 골랐든 선택한 문제를 풀고, 실패 로그가 있으면 그걸로 하네스를 고친다. *(작성자 주. 개선은 AutoSaddler 모듈에게 맡기는데, 이것은 별도의 논문으로 있으니 궁금하면 읽어보시길...)* 수정 전후의 실패는 '실패 패턴 리스트'를 보고 분류한다. 새로운 유형이면 패턴을 하나 추가.

### 실험 조건

- 벤치마크: GAIA2, Terminal-Bench 2.0
- 에이전트: GPT-5.5 (모든 곳에 이것만 사용)
- 총 실행 예산: GAIA2 1400회, Terminal-Bench 2.0 490회
- 핵심은 하네스를 고치는 AutoSaddler는 고정하고 과제 순서만 바꾸는 것 -> 무작위 vs. ActiveSaddler.

### 실험 결과

- 무작위 vs. ActiveSaddler의 대결에서는 ActiveSaddler 승리!
- 실패 패턴으로 과제를 묶는 전략이 유효했다. 그러니까 패턴별로 각개 격파가 효과가 있었다는 얘기. 반면에 벤치마크에서 제공된 과제 유형별로 묶었을 때는 효과가 덜했다.
- API 호출 비용 절감: 배치 선택 비용은 늘었지만, 같은 검증 점수에 도달하는 데 드는 전체 비용은 줄었다.
- ActiveSaddler를 다른 개선기(GEPA)에 붙여도 성능이 향상됐다.
